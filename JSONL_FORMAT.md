# Claude JSONL File Format

This document describes the structure of Claude conversation log files stored in JSONL (JSON Lines) format.

## File Location

Claude conversation logs are stored at:
```
~/.claude/projects/-home-florian-buildgit-[project-name]/[session-id].jsonl
```

Each line in the file is a separate JSON object representing a log entry.

## Entry Structure

### Common Fields

All entries share these base fields:

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Entry type: `"user"`, `"assistant"`, `"summary"`, etc. |
| `timestamp` | string | ISO 8601 timestamp (e.g., `"2025-01-12T10:30:45.123Z"`) |
| `requestId` | string | Identifies unique API request. **Multiple entries can share the same requestId** |
| `uuid` | string | Unique identifier for this specific log entry |
| `parentUuid` | string | UUID of the parent message in the conversation tree |
| `sessionId` | string | Session identifier |
| `message` | object | Contains the actual message data (see below) |

### Message Object

The `message` object contains:

| Field | Type | Description |
|-------|------|-------------|
| `role` | string | `"user"` or `"assistant"` |
| `content` | string or array | Message content (see Content Structure below) |
| `model` | string | Model identifier (e.g., `"claude-sonnet-4-5-20250929"`, `"claude-3-5-haiku-20241022"`) |
| `usage` | object | Token usage statistics (only present in assistant responses) |

### Content Structure

Content can be either:

1. **Simple string**: Plain text message
   ```json
   "content": "Hello, how can I help?"
   ```

2. **Array of content blocks**: Mixed content with text, tool use, and tool results
   ```json
   "content": [
     { "type": "text", "text": "Let me read that file." },
     { "type": "tool_use", "id": "toolu_123", "name": "Read", "input": {...} }
   ]
   ```

**Content Block Types:**
- **Text blocks**: `{ "type": "text", "text": string }`
- **Tool use blocks**: `{ "type": "tool_use", "id": string, "name": string, "input": object }`
- **Tool result blocks**: `{ "type": "tool_result", "content": any, "tool_use_id": string }`

**Important**: Not all entries have text content. Tool use and tool result entries often contain no displayable text.

### Usage Object

The `usage` object tracks token consumption for API calls:

| Field | Type | Description |
|-------|------|-------------|
| `input_tokens` | number | Input tokens sent to the model |
| `output_tokens` | number | Output tokens generated by the model |
| `cache_creation_input_tokens` | number | Tokens used to create prompt cache |
| `cache_read_input_tokens` | number | Tokens read from prompt cache |
| `service_tier` | string | Service tier used (e.g., `"default"`) |

**Optional nested cache fields:**
- `cache_creation.ephemeral_5m_input_tokens`: Tokens for 5-minute ephemeral cache
- `cache_creation.ephemeral_1h_input_tokens`: Tokens for 1-hour ephemeral cache

**Important Notes:**
- Only assistant response entries contain `usage` data
- Not every assistant entry has usage data
- Usage data represents actual API consumption for billing

## Deduplication

**Critical**: Multiple JSONL entries can share the same `requestId`. Each `requestId` represents one API request/response cycle.

When calculating costs or aggregating token usage:
- **Deduplicate by `requestId`** to avoid counting the same API call multiple times
- Use a Set to track seen `requestId` values
- Process only the first occurrence of each unique `requestId`

Example deduplication logic:
```javascript
const seenRequestIds = new Set();
messages.forEach((msg) => {
  const usage = msg.message?.usage;
  if (usage && msg.requestId) {
    if (seenRequestIds.has(msg.requestId)) {
      return; // Skip duplicate
    }
    seenRequestIds.add(msg.requestId);
    // Process unique API call...
  }
});
```

## Cost Calculation

To calculate API costs from usage data:

### Anthropic Pricing (per million tokens, as of January 2025)

| Model | Input | Output | Cache Write | Cache Read |
|-------|--------|--------|-------------|------------|
| claude-3-haiku | $0.25 | $1.25 | $0.30 | $0.03 |
| claude-3-5-haiku | $0.80 | $4.00 | $1.00 | $0.08 |
| claude-haiku-4-5 | $1.00 | $5.00 | $1.25 | $0.10 |
| claude-3-5-sonnet | $3.00 | $15.00 | $3.75 | $0.30 |
| claude-sonnet-4-5 | $3.00 | $15.00 | $3.75 | $0.30 |
| claude-4-1-sonnet | $5.00 | $25.00 | $6.25 | $0.50 |
| claude-opus-4 | $15.00 | $75.00 | $18.75 | $1.50 |

**Cache Write Pricing**: Cache creation tokens are billed at 1.25× the input token price.

**Cache Read Pricing**: Cache read tokens are billed at 0.1× the input token price.

### Cost Formula

```javascript
function calculateCost(usage, pricing) {
  const inputCost = (usage.input_tokens || 0) * pricing.input / 1_000_000;
  const outputCost = (usage.output_tokens || 0) * pricing.output / 1_000_000;
  const cacheWriteCost = (usage.cache_creation_input_tokens || 0) * pricing.cacheWrite / 1_000_000;
  const cacheReadCost = (usage.cache_read_input_tokens || 0) * pricing.cacheRead / 1_000_000;

  return inputCost + outputCost + cacheWriteCost + cacheReadCost;
}
```

## Known Limitations

1. **JSONL files may be incomplete**: The data in JSONL files doesn't always match the output of Claude's `/cost` command, which suggests the CLI uses a different or more complete data source for cost calculation.

2. **Token count discrepancies**: Aggregating tokens from JSONL entries may not match actual billed amounts shown by `/cost`.

3. **Multiple log entry types**: Not all entries represent API calls. Filter for entries with `message.usage` to find actual API requests.

4. **Empty content entries**: Some entries (especially those with only tool_use or tool_result blocks) may have no displayable text content.

## Processing Tips

1. **Filter for text content**: When displaying messages, filter out entries with no text to avoid showing empty markers.

2. **Extract text properly**: Handle both string content and array content:
   ```javascript
   const contentText = typeof content === 'string'
     ? content
     : Array.isArray(content)
       ? content.map(c => c.text || '').join(' ').trim()
       : '';
   ```

3. **Validate usage data**: Check that `message.usage` exists before trying to access token counts.

4. **Use requestId for aggregation**: When summing tokens or costs, always deduplicate by `requestId` first.
